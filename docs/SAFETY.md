# LayerGit Safety

LayerGit is designed around explicit write operations. It should be possible to
preview or explain what will happen before source repos change.

## Source of Truth

- `.layer/cache/<layer>/` repos are the source of truth.
- `buildtree/` is generated output.
- LayerGit never commits or pushes.
- Masked providers are not deleted.

## Doctor

Run:

```bash
layer doctor
layer doctor --json
layer doctor --strict
```

`doctor` checks workspace initialization, output path, write layer, layer cache
repos, Git status, stale ownership, unowned buildtree files, hidden selections,
overlaps, local-only layers, and locally detectable unpushed commits.

Exit codes:

- `0`: no errors
- `1`: warnings only with `--strict`
- `2`: errors found
- `3`: not a LayerGit workspace or invalid invocation

## Dry Run

Risky operations support previews:

```bash
layer compose --dry-run
layer apply common/util.c --dry-run
layer apply --new --dry-run
layer apply --all --dry-run
layer apply common/util.c --to board-support --dry-run
layer apply common/util.c --delete --dry-run
layer use common/util.c vendor-sdk --dry-run
layer use legacy/unused.c board-support --hide --dry-run
```

Dry-run output does not modify layer cache repos, `buildtree/`, ownership
metadata, lock files, or the Git index.

## Dirty Buildtree Protection

LayerGit refuses to silently overwrite or reroute a generated file that has
unapplied buildtree edits.

Choose an explicit action:

```bash
layer apply common/util.c
layer apply common/util.c --to board-support
layer compose --clean
```

`apply` keeps the edit by writing it to the current owner. `apply --to` copies
the current buildtree content into another layer and assigns the path there.
`compose --clean` is the explicit discard/regenerate path.

## Use, Hide, Apply, Delete

`layer use <path> <layer>` only selects an existing provider. If the target
layer does not provide the path, LayerGit fails and suggests explicit choices:

```bash
layer use common/util.c board-support --hide
layer apply common/util.c --to board-support
```

`layer use --hide` suppresses inherited lower-layer providers without changing
source repos.

`layer apply <path> --to <layer>` copies the current buildtree file into the
selected layer and assigns the path to that layer.

`layer apply` copies buildtree edits back to the current owning layer or write
layer.

`layer apply <path> --delete` applies a missing buildtree file as a source deletion in
the current visible owning layer. It does not delete masked providers.

## Safety Table

| Command | Source repo changed? | Provider selection changed? | Stages by default? | Purpose |
|---|---:|---:|---:|---|
| `layer use <path> <layer>` | no | yes | no | Select an existing provider |
| `layer use <path> <layer> --hide` | no | yes | no | Suppress inherited lower-layer file |
| `layer apply <path>` | yes | no | no | Apply edit to current owning layer |
| `layer apply <path> --to <layer>` | yes | yes | new files only | Apply current buildtree content to a chosen layer |
| `layer apply <path> --stage` | yes | no | yes | Apply and stage edit |
| `layer apply <path> --delete` | yes | yes/cleared | yes | Delete from owning source layer |
| `layer compose` | no | no | no | Regenerate `buildtree` |

Use `--stage` or `--no-stage` where supported. LayerGit stages only the file it
changed and does not stage unrelated dirty files.

## Stale Ownership and Unowned Files

Stale ownership means `buildtree/` still contains a file previously generated by
LayerGit, but the current layer configuration no longer owns that path.

Unowned files are files in `buildtree/` that LayerGit never generated. Normal
compose preserves them. `compose --clean` intentionally rebuilds the output tree.
